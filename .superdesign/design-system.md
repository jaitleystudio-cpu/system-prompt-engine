# SYSTEM PROMPT ENGINE — Semantic Forge Design System

## 1. Product context

System Prompt Engine (SPE) turns a raw user request into explicit semantic intent, a structured strategy, a rendered prompt, and a portable `.spe` artifact. The present product uses a real local Web Worker/WASM path, can operate as an offline PWA shell, exposes Intent and Prompt lenses, supports `.spe` import/export, and keeps history only when the user opts in.

The interface must explain:

`RAW THOUGHT → GOAL / CONSTRAINT / CONTEXT / UNKNOWN / PREFERENCE / OUTPUT → STRUCTURE → STRATEGY → PROMPT ARTIFACT → PORTABLE INTELLIGENCE`

Do not invent semantic analysis that the supplied source does not provide. Do not display fake scores, percentages, counts, proof badges, latency claims, customer claims, certifications, or production-readiness claims.

## 2. Target experience

Design a full-screen spatial product experience and its connected creative-instrument workspace.

- The opening viewport contains an immediately usable, accessible raw-thought composer.
- The story is one continuous scroll narrative with named camera acts.
- The scene is data-driven: visible semantic categories determine filament color, position, gaps, and material behavior.
- The workspace preserves Simple / Inspect / Pro depth and Prompt / Intent / Changes / Techniques / Artifact lenses without becoming a dashboard.
- Desktop and mobile are separate compositions.
- Reduced motion is a premium authored composition, not a broken fallback.
- The 3D layer is explanatory. All functional controls and text are standard DOM.

## 3. Brand idea: Semantic Forge

**Meaning becomes load-bearing.**

A longitudinal semantic workpiece changes form:

1. A graphite ribbon carries raw language into an intake.
2. It separates into six labeled semantic filaments.
3. Smoked-titanium gates align the filaments into structure.
4. A warm refractive-metal strategy spine sequences them.
5. Ceramic-white planes close around the structure as a prompt artifact.
6. The artifact becomes a thin, inspectable `.spe` folio with intent, requirements, strategy, prompt, and lineage layers.

This is a precision compiler/press, not a literal blacksmith forge. No anvils, flames, sparks, molten metal, gears, pistons, steampunk, or industrial cosplay.

## 4. Forbidden visual forms

Never use:

- a diamond or faceted hero gem,
- an orb, sphere, globe, planet, nucleus, or circular token,
- a glowing brain,
- particle sphere or atom/orbital rings,
- holographic globe,
- crypto/Web3 visual language,
- generic floating-card halo,
- dashboard/KPI hero,
- capability card wall,
- blue/purple neon wash,
- cyberpunk HUD, scanlines, reticles, gaming UI,
- generic circuit-board traces,
- a central pedestal product reveal,
- serif hero typography,
- an invented logo, initials badge, emoji, generic glyph, or placeholder SVG.

## 5. Identity and copy

No durable real logo asset is selected. Use the complete text identity `SYSTEM PROMPT ENGINE` wherever a brand identity is needed. Do not invent a logo mark or use a standalone `SPE` initials badge in the new directions.

Experience title: `SEMANTIC FORGE`

Recommended truthful interface language:

- Hero: `Give thought a structure it can travel in.`
- Composer label: `RAW THOUGHT`
- Placeholder: `What do you want to accomplish?`
- Primary action: `COMPILE INTENT`
- Stage verbs: `READ / SEPARATE / STRUCTURE / STRATEGIZE / RENDER / CARRY`
- Semantic labels: `GOAL / CONSTRAINT / CONTEXT / UNKNOWN / PREFERENCE / OUTPUT`
- Artifact: `PROMPT ARTIFACT` and `.spe`
- Skip link: `Skip cinematic story`

Keep copy compact and editorial. Avoid “revolutionary,” “magic,” “perfect,” “verified,” “smarter,” “10x,” “world-class,” and ungrounded superlatives.

## 6. Typography

Typography is advanced, precise, technical/editorial, and entirely sans-first.

- Display/body: `Inter Tight`, `Inter`, `"Helvetica Neue"`, `Arial`, sans-serif for draft portability. Use condensed width, variable weight, optical size, and tight tracking to create distinction; do not introduce serif or decorative display fonts.
- Technical: `"IBM Plex Mono"`, `"SFMono-Regular"`, `Consolas`, monospace.
- Hero display: 72–112 px desktop, 44–62 px mobile; compact line-height `.88–.98`; maximum 8–11 words.
- Section display: 46–76 px desktop, 34–48 px mobile.
- Body: 16–20 px, line-height 1.45–1.6.
- Labels: 10–12 px mono/sans, uppercase, tracking `.10–.16em`; do not overtrack.
- Use tabular numerals only for real runtime values.
- Default alignment is left. Center alignment is reserved for a single transitional artifact frame.

## 8. Materials and lighting

- Deep graphite: matte, light-absorbing environment; roughness .82–.96.
- Smoked titanium: dark anisotropic metal; narrow specular response, no chrome mirror.
- Smoked glass: edge-bonded inspection planes only; use sparingly and avoid generic frosted cards.
- Ceramic: warm off-white, low gloss, subtle microtexture, soft bevels.
- Warm refractive metal: brushed/oxidized brass family with restrained edge refraction.
- Filaments: thin internally lit fibers; luminosity remains localized without bloom clouds.

Lighting:

- One warm grazing key, one broad cool-neutral ceramic fill, narrow white edge lights.
- Black levels remain deep; avoid lifted blue fog.
- Occlusion and foreground silhouettes create density.
- Atmospheric haze is near-neutral charcoal and only separates depth planes.

## 9. Geometry and composition

- Primary forms: rails, combs, tensioners, indexing gates, dies, blades, layered planes, folded folios.
- Off-axis perspective and asymmetric balance.
- A clear lower-left foreground intake and center-right process depth in the opening frame.
- One continuous longitudinal workpiece persists across all acts.
- Rounded rectangles are controls, never the environmental grammar.
- No complete spheres or orbital paths.
- No random particles. If motes appear, they must be extremely sparse material dust with no semantic role.

## 10. Desktop act structure

### 00 / RECEIVE

Low off-axis camera inside a dark precision hall. Raw graphite ribbon enters from the near foreground. Full text identity sits at top left; compact act index at right. The accessible composer is an edge-bonded intake tray integrated into the scene, not a detached card. Hero copy is left weighted. Include `Skip cinematic story`.

### 01 / SEPARATE

Camera tracks beside the workpiece. Six semantic filaments peel apart with anchored, readable labels. Unknown remains an open span; Constraint is a stop; Preference is a bend. Show relationships, not metrics.

### 02 / STRUCTURE

Filaments route through titanium indexing gates and become a spatial scaffold. Use sectional close-ups, depth, and occlusion. This act should most clearly communicate the product's semantic model.

### 03 / STRATEGIZE + RENDER

Warm metal spine threads the scaffold. Ceramic planes fold in sequence. Prompt text is crisp DOM typography on a large inspection surface. The artifact should feel usable, not ceremonial.

### 04 / CARRY

Pull back to reveal a thin `.spe` folio with inspectable layers. Transition directly into the workspace.

Orientation is a restrained vertical act rail, not clickable chapter cards.

## 11. Workspace

Treat the workspace as a creative workbench.

- Center: one large prompt/artifact inspection bench.
- Left edge: raw thought and Intent Lens as a vertical material stack.
- Right edge: one sliding lens rail for changes, techniques, and artifact inspection.
- Top datum: actual phase, target, and local/offline status.
- Bottom action edge: Copy Prompt, Download `.spe`, JSON, Import `.spe`.
- History: closed material drawer with explicit opt-in and clear controls.
- Simple mode removes side instruments; Inspect reveals semantic layers; Pro reveals engine truth.
- Never arrange the workspace as a grid of equal cards or KPI tiles.
- Absent data shows `Unavailable` or `—`, never decorative zeroes.

## 12. Direction B adaptation: Semantic Observatory

Direction B uses the same colors, typography, materials, semantics, truth constraints, and wordmark.

Instead of a physical compiler hall:

- compose a horizontal semantic specimen across a deep field,
- use a macro inspection camera,
- reveal topographic depth slices and smoked-glass cross-sections,
- connect annotations with precise leader lines,
- treat scroll as movement along one specimen,
- use generous editorial negative space.

It must remain spatial and continuous, not become a dashboard, report, node graph, table, or card wall.

## 13. Controls

- Primary action: ceramic/warm-metal, dark text, 48–56 px height, precise rectangular form with 8–12 px radius; never a glowing cyan pill.
- Secondary action: graphite/titanium border, ceramic text.
- Textarea: transparent/dark intake surface, visible label, strong ceramic input text, minimum 96 px height desktop and 112 px mobile.
- Tabs/lenses: edge-mounted segmented rail with clear selected plane, not floating pills.
- Focus: 2 px warm highlight plus 2 px void separation.
- Hover is material/position response under 2 px, not bloom.

## 14. Motion

- Motion expresses material transformation and camera progression.
- Use authored camera states, slow tension, decisive lock, and short material settle.
- No ambient auto-rotation.
- No cursor trail, magnetic swarm, or continuous decorative motion.
- Scroll remains native and reversible.
- Compile state may animate the real active stage only.
- Recommended motion character: restrained, high mass, critically damped.

## 15. Mobile

Mobile is a portrait cutaway, not scaled desktop.

- Vertical workpiece travels through stacked forge sections.
- Composer is a stable lower-third intake tray with thumb-reachable primary action.
- One semantic label enters at a time; six labeled lines remain reviewable.
- Camera moves are replaced by sectional cuts and subtle depth planes.
- Workspace is one bench plus bottom-sheet lenses.
- No hover requirement, tiny annotation, horizontal story overflow, or hidden composer action.

## 16. Reduced motion

- Five authored still camera plates.
- No camera interpolation, filament travel, parallax, fog drift, shimmer, or automatic motion.
- Use immediate state changes or a single short opacity crossfade.
- Preserve all material richness, labels, and composition.
- Show semantic transformation through shape and ordered content.

## 17. Accessibility

- All functional content is DOM-native.
- Canvas is `aria-hidden` and has an equivalent ordered semantic story.
- Visible keyboard focus; logical focus order; minimum 44 px targets.
- WCAG AA contrast minimum.
- Live regions announce only real compile phases.
- User can skip the cinematic sequence and reach the workspace.
- Color, material, and motion are never the only carriers of meaning.

## 18. Reference-image handling

Two temporary canvas reference nodes will be supplied:

1. Metallic knot/monogram mood: learn from black negative space, manufactured metal response, hard rim light, and silhouette confidence. Do not copy the knot, orbital form, chrome initials, violet/blue light, or serif tagline.
2. Intent Core theater: learn from foreground/midground/background staging, focal-plane controls, material density, and cinematic camera impact. Do not copy its central globe, crystal, fantasy scenery, halo of cards, dashboard strip, or fabricated proof metrics.

The target is comparable premium impact and material authority with an original Semantic Forge identity.

## 19. Hard fidelity instruction

Use only the fonts, colors, spacing, materials, semantic labels, component styles, and visual rules defined here. Do not introduce fonts, colors, gradients, logo marks, decorative symbols, visual metaphors, metrics, cards, or claims outside this system.
