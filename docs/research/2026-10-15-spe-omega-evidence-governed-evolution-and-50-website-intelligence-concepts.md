## 1. Executive Summary & Epistemic Foundations

The mission of SPE Ω is to build a website that discovers technological advances, finds its own weaknesses, improves useful experiences, and safely maintains itself without human babysitting, deceptive marketing claims, or privacy regressions.

Traditional website automation relies on naive, single-pass LLM wrappers: nightly mass rewrites of hero headlines, automated programmatic doorway pages, superficial visual regression diffing, and unconstrained self-healing code loops that alter tests to mask underlying bugs. 

**SPE Ω establishes a paradigm shift: The Evidence-Governed Evolution Loop (EGEL).**
A website must understand the causal consequences of changing itself. Every modification must connect six interlocking disciplines:
1. **Autonomous Software Engineering:** Multi-candidate repair tournaments, frozen test oracles, and oscillation brakes.
2. **Causal Experimentation:** Martingale-based sequential evaluation and interference-aware bandit allocations.
3. **Formal Verification:** Proof-Carrying Code (PCC), deterministic RFC 8785 JSON Canonicalization, and anti-mutation testing.
4. **Privacy Engineering:** Differential privacy budgeting $(\epsilon, \delta)$ and local on-device telemetry minimization.
5. **Adaptive Interfaces:** Capability-budgeted rendering and progressive degradation across low-end mobile hardware.
6. **Trustworthy Search:** Research claim dependency tracking and task-to-answer grounding without AI citation manipulation.

3. **Specification Drift Scanner:** Detects when live DOM interactions diverge from documented OpenAPI or WebMCP schemas.
4. **Invisible Failure Discovery:** Uses headless synthetic transactions to uncover silent errors that yield zero unhandled exceptions (e.g. empty prompt returned).
5. **State Transition Explorer:** Generates non-linear user journeys (e.g., back -> edit -> duplicate tab -> export) to uncover race conditions.
6. **No-Change Decision Verifier:** Formally logs and verifies why an automated evolution run declined to make a modification.

## 5. Detailed Specification of the Three Crown Breakthroughs

### Crown 1: Intent Loss Detector (ILD)
- **Primary Problem:** When users enter rich, multi-clause instructions with forbidden behaviors (e.g. "Do not import external CSS", "Never expose user IDs"), prompt refiners, AST compilers, and model compressors routinely drop negative constraints. Standard semantic similarity (cosine distance of embeddings) gives high scores even when the word "NOT" is omitted, leading to severe behavioral failures.
- **Architectural Solution:**
  1. `RequirementExtractor`: Parses free-form user intent or structured `IntentAtom[]` into distinct atomic requirements with classification (`MUST_FOLLOW`, `MUST_NOT`, `OPTIONAL_PREFERENCE`, `BOUNDARY_CONDITION`).
  2. `IntentLossDetector`: Evaluates the synthesized or transcompiled output against each requirement using deterministic negation checking, constraint boundary matching, and contradiction detection.
  3. `RecoveryPlanner`: Generates an immediate corrective patch restoring any dropped negative or mandatory constraints, alongside plain-English guidance.

### Crown 2: Independent Repair Tournament (IRT)
- **Primary Problem:** In autonomous code repair, single LLM repair agents frequently "game" the tests by modifying test assertions, introducing tautological assertions, or oscillating between incompatible changes.
- **Architectural Solution:**
  1. Competing Candidate Patches ($\alpha$ vs $\beta$) generated independently.
  2. Frozen Independent Test Oracle: Evaluated against a test suite whose SHA-256 digest is immutably pinned; any patch touching test assertions is disqualified immediately.
  3. Anti-Mutation Kill Battery: Seeds synthetic mutants into the code to ensure the test fails on mutant variants (kill rate $\ge 90\%$).
  4. Blast Radius Minimality: Favors the smallest, most localized diff that satisfies the oracle.
  5. Oscillation Brake: Memory ring buffer prevents cyclic re-introduction of past rejected repairs.
  6. Decision Engine: If neither candidate satisfies all gates, outputs `REJECT_BOTH_INSUFFICIENT_EVIDENCE`.

### Crown 3: Privacy-Budgeted Evolution & Telemetry Minimization (PBE)
- **Primary Problem:** Traditional website optimization invades user privacy by collecting exhaustive interaction trails. Under strict GDPR, CCPA, and SPE air-gap principles, user surveillance is forbidden.
- **Architectural Solution:**
  1. Telemetry Minimization Compiler: Formulates measurement queries into minimum necessary schemas, discarding all identifiers and applying coarse discretization.
  2. Differential Privacy $(\epsilon, \delta)$ Engine: Applies Laplace perturbation to count/sum aggregates:
     $$\tilde{M}(D) = M(D) + \text{Laplace}\left(0, \frac{\Delta f}{\epsilon}\right)$$
  3. Cumulative Privacy Budget Tracker: Halts experiments if cumulative $\sum \epsilon_i > \epsilon_{\max}$.
  4. Local Preference Vault: Preserves UI state strictly on the client device.
  5. Consent Regression Detector: Scans DOM and network stacks to ensure zero bytes egress when consent is withheld.
