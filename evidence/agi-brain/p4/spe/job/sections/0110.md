## 12.1 Understanding the Components of the Zero-Cost Product Law — Introduction to the Zero-Cost Product Law

### 12.1 Understanding the Components of the Zero-Cost Product Law — Introduction to the Zero-Cost Product Law The concept of a zero-cost product law (ZCPL) is rooted in the idea that every system component should be designed with minimal external dependencies, thereby reducing the likelihood of introducing vulnerabilities and ensuring the security and reliability of the overall system. The ZCPL aims to minimize any potential vectors for introducing new vulnerabilities by keeping all components as free or open-source as possible. At its core, the ZCPL is a set of principles that guide the design and implementation of systems in order to ensure they are inherently secure without relying on external factors such as paid APIs, cloud services, or ad targeting. The key elements of this principle include: #### 12.1.1 Free Core Library and Universal ABI One of the foundational components of the ZCPL is the free and open-source core library and universal Abstract Base Interface (ABI). This ensures that all parts of the system can be developed, tested, and deployed locally without requiring external dependencies or expensive cloud-based resources. This approach not only simplifies the development process but also reduces costs significantly. #### 12.1.2 ₹0 Owner Spend Target The second pillar of the ZCPL is the target to have no paid expenses required for core proofs within a specific Sprint proof (Sprint 4 network). This means that all necessary resources and infrastructure can be developed, tested, and deployed locally without any external costs such as cloud hosting or paid API keys. This reduction in cost not only lowers operational overhead but also ensures that the system remains secure by eliminating potential points of vulnerability. #### 12.1.3 No Prompt Sales Another crucial element is the exclusion of any form of prompt sales, including prompts being treated as a monetized SKU within the core library. This prohibition on selling prompts or treating them as an additional service means that the focus remains solely on improving and refining the system itself. #### 12.1.4 No Ad Targeting The ZCPL also prohibits any form of advertising SDKs or user-targeting ad pipelines from being included in the core library. This ensures that no external advertisements can be integrated, thereby reducing the risk of introducing new vulnerabilities through these means. #### 12.1.5 Dependencies and Free Open-Source Components Dependencies for tasks such as JSON schema validation and testing are kept free and open-source if a truly local dependency is required. This allows developers to leverage existing community-driven tools without being forced into using proprietary or expensive solutions. #### 12.1.6 Sprint Proof Validation Network Mode The core library and all related components must be validated locally, adhering to the `network_mode=NONE` specification in the project setup (Pyproject.toml). This ensures that all validation and proof work is done in a controlled local environment without any external dependencies or costs. #### 12.1.7 Allowed Components The allowed components of the ZCPL include tools, fixtures, and test fixtures that are already part of the core library, as well as documentation and conformance JSONL files. This means that only necessary and proven components are included in the system, reducing complexity and potential vulnerabilities. #### 12.1.8 Forbidden Cost Vectors Finally, a list of forbidden cost vectors is provided, including paid package registry dependencies for core, paid API keys (LLM, search, billing), hosted proofs requiring hosting / SaaS, prompt marketplaces within the core library, and ad targeting/telemetry sales. By focusing on these foundational principles, the ZCPL ensures that every component of a system remains secure and free from external vulnerabilities. This approach not only enhances security but also reduces costs by minimizing the need for external resources and services. #### Conclusion The zero-cost product law (ZCPL) is a crucial principle in securing software systems, especially those designed to be as accessible and affordable as possible. By adhering to these principles, developers can create secure systems without relying on expensive external dependencies or paying additional fees. This ensures that the system remains both reliable and efficient, reducing operational overhead and minimizing risk.
