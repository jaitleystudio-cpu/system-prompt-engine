### 13.1 Conditions for Hard Rules Compliance: Free Core, No Paid Expenditures — Introduction to Compliance Standards In crafting a comprehensive research and development (R&D) handbook focused on 'Verified Research in the System Prompt Engine (SPE)', it is essential to establish clear compliance standards that ensure all activities meet predefined criteria without compromising the integrity of the project. The hard rules outlined below, as per the documentation provided, serve this purpose effectively by ensuring free core libraries and a zero-cost owner spend target for core SPE development. **1. Free Core: The SPE Core Library and Universal ABI Remain Free to Build and Run Locally** One of the fundamental principles highlighted is that the primary component of the system, the SPE library, should be accessible and usable without any additional costs. This means that developers can freely build and run the core library locally, bypassing the need for a paid cloud environment or any additional dependencies. The freedom to operate in this manner not only simplifies the development process but also ensures consistent performance across various environments. **2. ₹0 Owner Spend Target: No Paid Cloud, Model APIs, Analytics, CI Extras Required** Another crucial aspect is the complete prohibition of any form of paid expenditures that could potentially compromise the integrity or functionality of the project. This includes avoiding expenses on cloud services, model API subscriptions, analytics tools, continuous integration (CI) extras, and even ad targeting systems within the core SPE framework. By adhering to this rule, the team maintains a clean slate for their development efforts, ensuring that all resources are purely for the benefit of the research project. **3. No Prompt Sales: The Core Does Not Sell Prompts or Treat Them as Monetized SKU in Core** Prompts, which serve as inputs within the SPE engine, should be considered part of the core functionality rather than a separate monetizable product. This rule mandates that any interaction with prompts must not result in additional costs or fees. By maintaining this approach, the team ensures transparency and fairness in their research model, preventing any form of exploitation through paid promotional tactics. **4. No Ad Targeting: Core Must Not Include Advertising SDKs or User-Targeting Ad Pipelines** To further enhance the integrity of the project, all components must be designed with user privacy and data protection at the forefront. This includes avoiding any ad targeting mechanisms within the core SPE framework. The absence of such features ensures that user interactions remain purely informational and non-intrusive, thereby maintaining trust among participants and stakeholders. **5. Dependencies Declaration: `pyproject.toml` Stay Free: `jsonschema` (+ `pytest` for Dev) Unless a Free Local Dep is Truly Required** Dependencies are an essential part of any software project; however, they can sometimes introduce additional costs if not managed correctly. The documentation specifies that only free and local dependencies must be declared in the `pyproject.toml`. This rule ensures that even when using external libraries or tools, the team adheres to their zero-cost standard by declaring these dependencies clearly within their own codebase. **6. Sprint 4 Network: Validation and Conformance Run with `network_mode=NONE`** The validation process is crucial for ensuring that all components of the system operate as intended under normal conditions. The documentation explicitly states that validation should be conducted using a network mode set to `NONE`, indicating an environment designed without any paid dependencies or cloud services. **7. Allowed: Local Python, Local Fixtures, Local Tempfile Adapters Already in Tree** For local testing and debugging purposes, the team is encouraged to use local versions of Python packages and fixtures provided by their development environment. This practice ensures that all necessary tools are available within the confines of a clean checkout without requiring any external dependencies. **8.
