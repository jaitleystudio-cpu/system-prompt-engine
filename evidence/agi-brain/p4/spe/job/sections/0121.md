### 13.2 Conditions for Hard Rules Compliance: Free Core, No Paid Expenditures — Understanding Zero-Cost Principles

The Verified Research and Development (VRR) system prompt engine (SPE), under the Zero-Cost Product Law (ZCPL), operates on a foundation of zero-cost principles to ensure that development is both cost-effective and transparent. This section delves into the specific conditions required for compliance with the free core, no paid expenditures rule, which are essential for maintaining the integrity and affordability of SPE.

#### Free Core

The ZCPL mandates that the core library and universal ABI (Application Binary Interface) remain available in their entirety without any cost associated with accessing them. This is crucial because it ensures that developers can freely build and run SPE locally, bypassing the need to pay for cloud resources or third-party APIs. By adhering to this rule, SPE remains accessible for development purposes without additional financial burdens.

#### No Paid Expenditures

The rule also prohibits any form of paid expenditures related to core functionalities. This means that no paid package registry dependencies (e.g., LLMs, search services) can be included in the core, nor can any hosted or SaaS-based proof environments be required. Similarly, there is a strict prohibition against prompt marketplaces and targeting systems being integrated into the core.

#### Documentation and Conformance

In addition to these fundamental principles, SPE must adhere to additional conditions outlined in its documentation to ensure that it remains fully compliant with the ZCPL:

1. **Local Python Implementation**: The codebase should be entirely written using Python 3.x for local execution.
2. **Free Dependencies**: All dependencies mentioned in `pyproject.toml` and other manifest files must be declared as free or open-source, including specific packages like `jsonschema`, `pytest`, and others that may be required for development but not included in the core library itself. For instance:
   ```toml
   [tool.poetry.dependencies]
   jsonschema = { ^requires-python: "^30.25", "name"="jsonschema", "constraint"="^41.0.0" }
   pytest = { ^requires-python: "^6.25", "name"="pytest", "constraint"="^7.1.2" }

   [tool.poetry.dev-dependencies]
   ```

3. **Documentation and Conformance JSONL**: The system should include comprehensive documentation in a format like `conform.jsonl`, ensuring that all required specifications, rules, and guidelines are clearly documented.

#### Forbidden Cost Vectors

The document also outlines a list of cost vectors that must be avoided under any circumstances:

- **Paid Package Registry Deps for Core**: No dependencies on paid package registries should be included in the core library.
- **Paid API Keys (LLM, Search, Billing)**: No access to or payment for third-party APIs such as LLMs, search services, billing systems, or similar tools should be allowed within the core.
- **Hosting / SaaS Required for Proofs**: Any hosting service required for proof environments must not be included in the core.
- **Prompt Marketplace in Core**: The core library cannot include a prompt marketplace or any system that targets users or advertisers.
- **Ad Targeting / Telemetry Sales**: No ad targeting systems or telemetry sales mechanisms should be integrated into SPE.

These prohibitions are designed to maintain the integrity and affordability of SPE, ensuring that developers can focus on innovation without being burdened by unnecessary costs. By adhering to these strict conditions, SPE remains a reliable tool for researchers and developers looking to build AI applications in a cost-effective manner.

#### Conclusion

The Zero-Cost Product Law (ZCPL) is essential for maintaining the affordability of SPE, ensuring that it can be used as a platform for research without financial constraints. The rules outlined here ensure that all core functionalities remain free from additional costs, making it an ideal choice for those looking to develop AI applications quickly and efficiently. Compliance with these conditions guarantees that developers can focus on creating value-added content while staying within budgetary limits.
