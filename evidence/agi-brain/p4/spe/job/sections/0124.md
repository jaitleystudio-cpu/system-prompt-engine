## 13.5 Conditions for Hard Rules Compliance: Free Core, No Paid Expenditures — Examples of Compliant and Non-Compliant Actions In the realm of the System Prompt Engine (SPE), adhering to the stringent rules outlined in "Verified Research in the System Prompt Engine" is paramount for both developers and users alike. This section elaborates on compliance with these hard rules, providing examples of how they should be applied within various scenarios. ### 13.5.1 Compliance: Free Core The first rule stipulates that the core library and universal ABI must remain free to build and run locally without any paid cloud hosting or model APIs being required for proof sprinting. This ensures that developers can easily test their experiments on a local machine, fostering innovation and experimentation. **Compliant Action Example:** - **Local Python Environment**: Ensure your local development environment includes all necessary dependencies such as `jsonschema` and `pytest`. For this example, simply install these packages locally using pip: ```bash pip install jsonschema pytest ``` ### 13.5.2 Compliance: ₹0 Owner Spend Target The second rule mandates that no paid cloud hosting or model APIs are required for proof sprinting. This means developers can focus on their experiments without worrying about additional costs related to API fees or paid hosting services. **Compliant Action Example:** - **Core Library and Dependencies**: For local development, ensure that all dependencies required for the core library are included in your project’s `requirements.txt` file. Here is an example: ```bash jsonschema>=4.17.6 pytest>=7.2.1 ``` ### 13.5.3 Compliance: No Paid Package Registry Deps The third rule prohibits the use of paid package registry dependencies, such as LLMs (large language models) or search APIs that are not included in the free core. **Compliant Action Example:** - **Local Dependency Installation**: If you need specific packages for your experiments, ensure they are installed locally using pip. For example: ```bash pip install --upgrade sentence-transformers transformers==4.18.0 pydantic ``` ### 13.5.4 Compliance: No Paid APIs The fourth rule forbids the use of paid API keys for any purpose within the core library. **Compliant Action Example:** - **API Usage Restrictions**: For all experiments, ensure that no paid LLMs or search APIs are used in your proofs. Replace them with locally accessible alternatives if necessary. ```python # Non-paid implementation example from sentence_transformers import SentenceTransformer model = SentenceTransformer('all-MiniLM-L6-v2') ``` ### 13.5.5 Compliance: No Paid Hosting / SaaS Required The fifth rule stipulates that no hosting or SaaS services are required for proof sprinting. **Compliant Action Example:** - **Local Proof Runs**: Ensure your proofs run within a local development environment, avoiding the need to host code externally. ```bash python -m pytest --cov=your_experiment tests/ ``` ### 13.5.6 Compliance: No Paid Prompt Marketplaces The sixth rule prohibits the use of paid prompt marketplaces or targeting services that could sell prompts as a monetized SKU. **Compliant Action Example:** - **Ad-Free Core**: Ensure your core library is ad-free and does not include any advertising SDKs. ```bash # Non-paid example import requests def fetch_data(url): response = requests.get(url) return response.json() ``` ### 13.5.7 Compliance: No Ad Targeting / Telemetry Sales The seventh rule ensures that there is no advertising or telemetry data sales within the core library. **Compliant Action Example:** - **Free Core**: Ensure all dependencies are included locally in your project. - **₹0 Owner Spend Target**: No paid cloud hosting or model APIs required for proof sprinting. - **No Paid Package Registry Deps**: Use only free, open-source libraries and packages. - **No Paid APIs**: Avoid using any paid LLMs or search APIs within the core library. - **No Paid Hosting / SaaS Required**: Run proofs locally without external hosting or SaaS services. - **No Paid Prompt Marketplaces**: Ad-free core without selling prompts as a monetized SKU. - **No Ad Targeting / Telemetry Sales**: Ensure there is no advertising SDKs, telemetry data sales, or other targeting mechanisms.
