## 13.7 Conditions for Hard Rules Compliance: Free Core, No Paid Expenditures — Evaluating Compliance with Cited Studies

### 13.7 Conditions for Hard Rules Compliance: Free Core, No Paid Expenditures — Evaluating Compliance with Cited Studies To ensure that the Verified Research in the System Prompt Engine (SPE) project complies with its hard rules and maintains ethical integrity, it is crucial to evaluate adherence to the principles set forth by these rules. This evaluation involves a thorough examination of how each aspect of the SPE adheres to the zero-cost product law and other related constraints. #### Free Core Library The first rule stipulates that the core library and universal ABI must be free to build and run locally, without requiring any paid services or dependencies. To evaluate compliance with this rule, we need to ensure that: - **No Paid Services**: The SPE does not include any paid package registry dependencies for the core library or any other paid services such as APIs, analytics, or cloud hosting. - **Free Dependencies**: All required dependencies, including `jsonschema` and `pytest`, are declared in the `.gitlab-ci.yml` file under the `dependencies` section. This ensures that no additional paid services are required. #### ₹0 Owner Spend Target The second rule mandates a zero-cost owner spend target for core development, proofing requirements, and CI extras. To verify compliance with this rule: - **Local Development**: The SPE is designed to be developed locally using only the free dependencies declared in `pyproject.toml`. - **Proofs Requirements**: The proofs must run within an environment that requires no paid cloud services or model APIs. - **CI Extras**: There are no additional CI extras required, ensuring that the proofing process remains entirely free and local. #### No Prompt Sales The third rule prohibits any form of prompt sales or treating prompts as a monetized SKU. To confirm compliance: - **Prompts Not Sold**: The SPE does not sell prompts or promote them in core. - **No Monetization**: There are no paid LLM, search, billing, or model APIs included in the core. #### No Ad Targeting The fourth rule mandates that no advertising SDKs or user-targeting ad pipelines should be present. To validate compliance: - **Ad-Free Core**: The SPE does not include any ads or targeting features. - **User Data Protection**: All interactions within the core are conducted in a way that respects user privacy and data security. #### Dependencies The fifth rule stipulates that only free dependencies declared in `pyproject.toml` can be included. To ensure compliance: - **Free Dependencies**: The required dependencies, such as `jsonschema`, `pytest`, and any other necessary libraries, are explicitly listed and marked as free. - **No Additional Costs**: No additional paid services or tools are added to the core library. #### Sprint 4 Network The sixth rule specifies that validation and conformance must run with `network_mode=NONE`. To evaluate compliance: - **Local Validation**: The core is validated locally without any network dependencies, ensuring that all interactions are isolated within a local environment. - **No Paid Services Required**: This adherence to the `network_mode=NONE` ensures that no paid services or external dependencies are required for proofing. #### Allowed and Forbidden Cost Vectors The seventh rule lists which cost vectors are allowed and which are forbidden. To verify compliance with this: - **Allowed Costs**: - **Free Package Registry Deps**: The core library does not include any paid package registry dependencies. - **Free Dependencies in `pyproject.toml`**: All required dependencies are listed and marked as free. - **Forbidden Costs**: - **Paid Package Registries**: No paid API keys or LLM dependencies are included. - **Hosting / SaaS Required for Proofs**: The core development and proofs do not require hosting or cloud services. #### Proof Posture The eighth rule specifies that proofing must remain reproducible offline on a clean checkout with `python -m pytest`. To confirm compliance: - **Offline Reproducibility**: The SPE is designed to be tested offline, ensuring that every aspect of the core can be validated and proven without requiring any paid services or hosting. - **Clean Checkout**: All dependencies are isolated in a local environment, ensuring that each proof runs independently. #### Hard Rules Compliance By adhering to these hard rules and evaluating them through this process, we can confirm that the SPE project remains compliant with its stated goals.
