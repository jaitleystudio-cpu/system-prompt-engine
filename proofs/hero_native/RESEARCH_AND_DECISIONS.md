# Hero-only research and decision record

1. **Mission:** replace the production founder PNG with an understandable native animated story; preserve PR #44 custody and all non-hero owners. No deployment.
2. **Decomposition:** story comprehension, responsive composition, theme fidelity, motion accessibility, performance, provenance, founder review.
3. **Evidence plan:** capture the exact baseline; inspect real components and CSS; compare the same four viewport/theme/motion states; browser behavior tests, axe, TypeScript, bundle/network measurements, unchanged gate execution.
4. **Foundational source:** W3C WCAG 2.2 SC 2.2.2 explains user control of automatic movement, including pauses that persist after focus leaves. https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html (read 2026-09-27).
5. **Current source:** MDN prefers-reduced-motion documents the user media preference. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion (read 2026-09-27). Implement both initial and live preference handling.
6. **Contradictory evidence:** a polished still can communicate composition, but the actual baseline mobile screenshot places a very small PNG below a large void. A motion sequence can communicate process, but movement can also distract or hide information. Static semantics and finite motion resolve that conflict.
7. **Benchmark:** Norrly's public /app surface offers scroll recordings and screenshots, measured palettes and prompt previews. https://norrly.io/app (read 2026-09-27). Used only as a pattern-level benchmark for showing the experience and output. No assets, code, branding or authenticated library copied; no claim of a full interactive Norrly audit.
8. **Full-source interrogation:** read HeroStory, Hero, relevant theme/CSS owners, focused tests and deployment gate. Old tests explicitly required the PNG, so those hero assertions required replacement. Existing .spe-pipeline styles introduced absolute positioning and were removed from the new component after visual evidence showed clipping.
9. **Method verification:** local copy starts at the connector-verified PR head 1ff61b1b236971a30492a923c28d3d65a7cd9458. The original branch and unrelated evidence stay intact. Captures use the production Vite build on loopback, fresh browser contexts, no external hosting.
10. **Claim/evidence graph:** native motion → CSS keyframes plus advancing browser timelines; user control → keyboard pause/resume/replay checks; no PNG rendering → DOM and network assertions; mobile story → 320–700 layout checks and screenshots; themes → explicit and system live-change tests; reduced motion → zero hero animations and visible final prompt; containment → changed-file allowlist.
11. **Contradiction map:** old PNG test versus current instruction → replace the test; static asset beauty versus mobile comprehension → responsive native markup; automatic animation versus user agency → finite story and pause/replay; broad build versus frozen engine → report existing packaging failure without changing engine.
12. **Unknowns:** founder aesthetic acceptance, first-visit comprehension across real users, physical-device Safari, assistive-technology speech output, field Core Web Vitals, and full application packaging remain distinct from local hero checks.
13. **Twelve hypotheses:** (a) static PNG; (b) animated video; (c) sprite sequence; (d) Lottie; (e) Three.js scene; (f) Canvas drawing; (g) SVG-only illustration; (h) CSS/HTML narrative; (i) horizontal mobile shrink; (j) vertical mobile story; (k) endless loop; (l) finite story with replay.
14. **Falsification:** a violates live-hero request; b/c make semantic/theme adaptation difficult and add media bytes; d adds a new runtime; e has no demonstrated need; f loses native text semantics; g alone makes editorial text/layout less maintainable; i fails baseline mobile evidence; k adds distraction and ongoing work. These are task-specific engineering tradeoffs, not experimentally established universal claims.
15. **Survivors:** h + small decorative SVG fragment icons + j + l. Native text retains meaning; SVG provides image/waveform recognition; no new dependency.
16. **Decision/uncertainty:** restrained editorial split, actual example content, compact SPE seal, four output fields and a reviewable final artifact. “Perfect prompt” is the requested narrative title, not a measured claim of flawless model output; visible copy calls this an illustrative example and asks for review.
17. **Prototype:** implemented in HeroStory and hero-native.css; removed the obsolete final PNG CSS block only. No Create or architecture change.
18. **Measured proof:** see tests.json, before/after metrics, screenshots, recordings and performance.json. TypeScript and Vite checks are separate from full packaging.
19. **Replication:** repeat timeline checks plus independent test methods (DOM assertions, axe, source boundaries, screenshots, frame sampling, theme module smoke). Same local Chrome host is not independent third-party replication; do not claim it is.
20. **Integration gate:** local commit only, founder PASS/HOLD pending. HOSTING=FORBIDDEN. No push, merge, workflow, deploy or DNS action.

## Design audit, using the Product Design skill

Scope is the home hero only. Screenshot sequence: dark desktop, light desktop, mobile, reduced motion. Baseline mobile fails storytelling because the image is tiny and separated from the headline by empty space; baseline light mode keeps an opaque dark image rectangle. Native output fixes those observed issues. Stage names and sample content are real text. Remaining aesthetic and comprehension judgment belongs to the founder; screenshots and axe alone are not a full WCAG conformance assessment.
